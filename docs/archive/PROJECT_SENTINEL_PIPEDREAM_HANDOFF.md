## Notion Setup

Notion database name:

**Projects Command Center**

Important rule:

Each project row has a property named:

**Repo Name**

Use **Repo Name** as the matching key between GitHub and Notion.

Do not rely on the Notion page title.

Matching should be **case-insensitive**.

Example:

```text
GitHub repo name: Tapcash
Notion Repo Name: tapcash
```

These should match.

Use logic like:

```js
githubRepoName.toLowerCase() === notionRepoName.toLowerCase()
```

Known Notion Repo Name values:

```text
acc
AlphonsoEcosystem
shiporex
agents-ops-board
aegis
tapcash
session-guard
founder-social-club
costpilot
mint
obsidian-studio
obsidian-media
```

## Main Workflow Goal

When a GitHub push happens:

1. Receive the GitHub push event.
2. Extract useful repo and commit data.
3. Find the matching Notion project row where `Repo Name` equals the GitHub repository name.
4. Update the Notion project row with the latest commit data.
5. Try to append a changelog entry to the project page.
6. Send a Telegram success alert.
7. If no matching project is found, send a Telegram warning.
8. If Notion update fails, send a Telegram error alert.

## Step 2 — Fix `extract_github_data`

Extract these values from the GitHub push payload:

- repository name
- repository full name
- repository URL
- ref
- branch name
- latest/head commit message
- latest/head commit hash
- latest/head commit URL
- commit author name
- commit author email if available
- commit timestamp
- changed files
- files changed count
- added files
- modified files
- removed files
- total commits in push
- whether it is a marketing/design/image-only update

Use `payload.head_commit` as the latest commit if available.

Fallback:

If `payload.head_commit` is missing, use the last item in `payload.commits`.

Changed files:

Combine these arrays if available:

- `added`
- `modified`
- `removed`

If changed files are unavailable, continue without failing.

Branch extraction:

If `payload.ref` is:

```text
refs/heads/main
```

then branch should be:

```text
main
```

Remove the `refs/heads/` prefix.

Expected output variables:

```text
repoName
repoNameLower
repoFullName
repoUrl
branchName
commitMessage
commitHash
commitUrl
authorName
authorEmail
commitTimestamp
changedFiles
changedFilesText
filesChangedCount
addedFiles
modifiedFiles
removedFiles
isMarketingOnlyUpdate
commitCount
```

## Marketing / Design / Image-Only Logic

A commit is marketing/design/image-only if **every changed file** is either one of these extensions:

```text
.png
.jpg
.jpeg
.webp
.svg
.gif
.fig
.psd
.ai
```

or the path contains one of these folders:

```text
/assets
/images
/public
/marketing
/brand
/design
```

If there are no changed files available, do not mark it as marketing-only.

```

```

Optional fields, only if they exist and are easy to update:

```text

```

Do not fail the whole workflow if an optional Notion property is missing.

If a property does not exist:

- Skip it
- Log a clear note
- Continue

Basic non-AI summary:

```text
Latest commit on [branch] by [author]: [commit message]. Files changed: [count].
```

Simple Version 1 risk label, if easy:

- Low: marketing/image/design-only update
- Medium: normal code change
- High: files include env, auth, security, payment, database, production, deployment, or config paths/files

If Risk Level is difficult to map, skip it in Version 1.
